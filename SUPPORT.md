# Support policy

S11tnext is maintained as an open-source project. Public support is provided through GitHub issues on a
best-effort basis; no response time or resolution time is guaranteed.

## Where to ask

- Use a bug report for reproducible product defects.
- Use a feature request for a concrete capability or workflow gap.
- Use an adoption report for a redacted production use case or to join the design-partner program.
- Report suspected vulnerabilities only through
  [GitHub private vulnerability reporting](https://github.com/ugnoguchigxp/s11tnext/security/advisories/new).

Do not post credentials, proprietary prompts, customer data, or private repository links. A minimal,
synthetic reproduction is preferred.

## Supported environments

The supported Node.js versions and package-manager version are declared in `package.json` and exercised
by CI. Security fixes target the latest published release line. Compatibility fixes for older releases
may be declined when upgrading is practical.

## Response expectations

Maintainers triage security reports first, then regressions with a reproduction, then other requests.
Issues may be closed when they cannot be reproduced, are outside the documented trust boundary, or have
had no requested follow-up for 30 days. Commercial support and private consulting are not currently
offered.

## Design partners

Teams evaluating S11tnext in a real application can join the time-boxed
[design-partner program](./docs/adoption/design-partner-program.md). Participation does not create a
service-level agreement and never requires sharing prompt contents or customer data.
